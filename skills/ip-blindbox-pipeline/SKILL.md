# IP 盲盒快捷工作流（通用版）

把一个已有的 IP 形象，做成「N 款公仔 + 隐藏款 + 彩蛋」的盲盒，并产出：印刷盒面、照片级渲染、在线开盒网页、产品介绍。
参考成品：大巴赛博盲盒（https://github.com/bigchen316/daba-cyber-blindbox 的 `docs/产品介绍.md`、`site/index.html`）。如果用户手上已有一套做好的网页源码和 Blender 脚本，优先复用，只换素材和文案；没有就按下面每一步的规格从头写。

## 工具包（本 skill 自带，开箱即用）

```
scripts/blender/1_产品主图.py     产品主图：盒子 + 公仔 + 星空背景
scripts/blender/2_盒子转盘.py     盒子 360°：72 帧透明背景
scripts/blender/3_公仔转盘.py     公仔 360°：每款 24 帧 + 正面主图
scripts/site/build_site.py       渲染图 → 可开盒网页（index.html + figs/）
scripts/site/template.html       开盒网页模板（星空陈列台、炸开、公仔可转、收藏、集齐召唤彩蛋）
scripts/site/config.example.json 系列配置示例（大巴赛博盲盒）
```

让用户按这个结构建一个项目文件夹，三个 Blender 脚本只需要改顶部的 `BASE`：

```
<项目文件夹>/
  config.json        复制 config.example.json 改：标题、slogan、每款的名字/描述、哪款是隐藏款、彩蛋
  盒面/              正面.png 背面.png 左侧面.png 右侧面.png 顶面.png 底面.png
  3D模型/            01_基础款.glb …（文件名 = config.json 里的 model）
  渲染/              Blender 脚本自动输出
  网页/              build_site.py 自动输出
```

脚本顶部 `QUICK_TEST = True` 先出小图试跑（4 帧、低采样），构图没问题再改回 `False`。
网页：`pip install pillow numpy` 后运行 `python scripts/site/build_site.py <项目文件夹>`。

## 0. 开工前先问清（一次问完）
- IP 名字、识别特征（颜色/服装/标志物）、系列主题和一句 slogan
- 款式数量：常规几款、隐藏款是哪款、概率（参考 1/12）、有没有不售彩蛋
- 电脑配置（显卡型号决定渲染时间）和是否已装 Blender
- 用户偏好：喜欢自己改脚本 → 每次只给「改第几行、改成什么」，不要整段替换
- 版权：不模仿任何品牌（如 POP MART）的商标、版式和名字

## 1. 2D 款式设计
- 先定母版：三视图 + 设计规范（颜色、比例、禁用项）。
- 每款一张全身正面图，同一视角、同一光线、纯色背景，方便 3D 生成。
- 文件命名 `01_基础款.png … 08_xxx.png`，后续所有环节沿用同一编号和名字。

## 2. 3D 建模（混元3D，免费，由用户手动完成）
这一步 AI 做不了：混元 3D 要用户自己在网页（https://3d.hunyuan.tencent.com）登录、上传图片、下载 GLB，没有可直接调用的接口。不要说"我无法代劳"就停下，按下面带着用户做完。

**AI 引导用户：**
- 先列一张清单：每款的 2D 图文件名 → 对应要保存的 GLB 文件名（例：`01_基础款.png` → `01_基础款.glb`），名字必须和 `config.json` 里的 `model` 一致。
- 给出操作步骤：打开混元 3D 网页 → 图生 3D → 上传这一款的正面图 → 选 V3.1、50 万面 → 生成 → 导出 GLB → 改成清单里的名字 → 放进 `<项目文件夹>/3D模型/`。
- 建议先只做 1 款，确认效果和流程都没问题，再批量做其余款。
- 告诉用户：每款生成要等几分钟；全部放好后回来说一声，或者只说"做好了 01、02"也行，可以分批交。
- Tripo 免费版只能导出低质量版本，不推荐。

**等待期间 AI 可以先做（不依赖 3D 模型的）：**
- 按第 0 步的信息写好 `config.json`（标题、slogan、每款名字/描述、隐藏款、彩蛋）。
- 第 3 步盒面的版式、配色方向和文案；正面要用的公仔渲染图先留位置。
- 把三个 Blender 脚本顶部的 `BASE` 改成用户的项目文件夹。

**用户说做好了之后，先检查再继续：**
- 列出 `3D模型/` 里的文件，和清单逐个对：缺哪款、哪个文件名对不上，直接告诉用户，不要自己猜着改名。
- GLB 文件只有几十 KB 或打不开 = 导出失败，让用户重新导出这一款。
- 生成的模型脚下常带一层薄底座：渲染脚本里按高度切掉最底层（cut = 高度 × 0.5%），不用让用户处理。
- 只要有 1 款到位，就可以先用 `QUICK_TEST = True` 跑这一款试渲染，不必等全部款做完。

## 3. 盒面设计
- 用 HTML 排版 6 个面（正/背/左/右/顶/底），浏览器（Playwright）截图导出 PNG：正侧面约 1001×1522，顶底 1001×1001。
- 推荐分工：正面=主角+标题+slogan；右侧=ALL MEMBERS 全款展示（隐藏款只放剪影+概率）；左侧=从 2D 到 3D；背面=信息卡+警示+二维码+条形码；顶面=撕拉条。
- 正面的公仔用 Blender 渲染图（去底座、加椭圆软阴影），不要用 2D 图硬抠，会抠坏白色鞋子。
- 先出 2~3 个配色方向给用户选，定稿后其余版本归为过渡文件。

## 4. Blender 渲染（三个脚本，见 scripts/blender）
- `产品主图`：盒子 + 公仔 + 星空/主题背景。
- `单盒转盘`：72 帧（每 5°）、透明背景、1600×2000、采样 160；有 `REDO=[帧号]` 只补渲坏帧。
- `公仔转盘`：每款 24 帧（每 15°）+ 一张 -20° 正面主图，1200×1500、采样 128；`ONLY=["02_篮球款"]` 一次只渲一款，防止电脑卡和闪退。
- 必踩的坑（脚本里已处理，新写脚本也要照做）：
  - 中文界面节点名会被翻译 → 按节点类型找 Principled BSDF，不按名字。
  - glTF 导入是四元数旋转 → 改 rotation_euler 不生效；最稳的是直接变换网格（mesh.transform）来转。
  - 降噪固定 `OPENIMAGEDENOISE`，否则会有部分帧没降噪带颗粒（看文件大小和每帧耗时是否一致来排查）。
  - 盒子材质用哑光（粗糙度约 0.58、低高光），否则转盘会晃眼。
  - 黑衣服发灰 → 曝光 -0.6、补光调低、AgX Medium High Contrast。
  - 背景景深太大会把星星虚化没：光圈 f/9 左右、星星做大做亮。
  - 闪退多是显存满：每渲完一款重启 Blender，关掉浏览器等占显卡软件，`use_persistent_data=False`。
- 用户改了脚本后一定提醒：Blender 文本编辑器要「文本→重新载入」，否则跑的还是旧代码。
- 渲完后先抽查：每款看 f_00 和 f_12 是否真的转了；同一组帧文件大小几乎一样 = 没转。

## 5. 盲盒网页（scripts/site/build_site.py 一条命令生成）
- 结构：一个网页模板 + 一个拼装脚本（把渲染帧、公仔图、盒面贴图转成 data URI 填进模板）：
  - 盒子转盘：72 帧裁切后转 webp（960×1200，质量 86）内嵌，拖动按角度切帧，不做相邻帧淡入（会重影）。
  - 开盒：盒子抖动鼓起 → 炸成满屏星星（canvas 粒子）→ 盒子消失、公仔高高跳出、落地压扁回弹；隐藏款用金色星星。
  - 公仔可转：每款 24 帧拼成 6×4 精灵图（单元 560px，webp 80），作为同目录 `figs/*.webp` 文件发布，不内嵌。
  - 收藏栏用 localStorage（包 try/catch）。
  - 彩蛋：集齐全部款 → 上 4 下 4 两层发光展台 → 依次化成星光汇入光球 → 光柱 → 彩蛋角色登场。
- 网页不要放声音；页面内嵌内容控制在 16MB 内（参考成品约 11MB）。
- 字体：Google Fonts 用 `media="print" onload="this.media='all'"` 异步加载，国内网慢或离线时页面先用系统字体（苹方/微软雅黑）显示，不会卡白屏；`<head>` 里放 `<link rel="icon" href="data:,">`，避免请求不存在的 favicon.ico 报 404。模板里都已处理。
- 用 Playwright 截图检查：开盒各时间点、再拆一盒、跳过、彩蛋全流程，看控制台没有报错。
- 发布为在线页面；本地另存一份 `index.html + figs/` 离线版。

## 6. 产品介绍
- 在线文档：一句话介绍、IP 形象特征表、款式表（含隐藏/彩蛋）、包装六面说明、开盒体验步骤、制作流程图、规格与文件位置。
- 展示网页：与盒子同一视觉（星空/主题色），首屏是可拖动的 360° 盒子 + 去开盒按钮，下面是全款卡片、彩蛋、盒面、开盒步骤、制作流程、规格。

## 7. 收尾整理
- 写 `00_目录说明.txt`（每个文件夹是什么、怎么用）和 `00_可删除清单.txt`（被取代的配色稿、旧脚本、带噪点的图等），删除交给用户自己确认。
- 网页源码打包成 `源码.zip` 存进用户文件夹。

## 沟通习惯
- 中文、简短；每步告诉用户「改哪一行、改成什么、大概要多久」。
- 长时间渲染建议一款一款来，渲完先让我抽查再继续。
